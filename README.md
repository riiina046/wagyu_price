# Git Lesson

## リモートリポジトリとローカルリポジトリとはそれぞれ何でしょうか？
- リモートリポジトリ　ネット上に配置して複数人で共有するためのリポジトリ。(個人開発にも使用可能)

- ローカルリポジトリ　開発者一人ひとりが使用するために自分のPC上に配置するためのリポジトリ。

## プッシュとマージの違いは何でしょうか？
- プッシュとは、ローカルで作成したコミットをリモートリポジトリに送信する操作で、マージとは、あるブランチの変更内容を別のブランチに取り込んで統合する操作です。


## コミットとプッシュの違い
- コミットは、自分のPCだけの変更確定を行い、プッシュは、その変更をリモートへ共有する違いがあります。

## コミットのメッセージはどのように書いてあげるのが適切でしょうか？
- 履歴を見た際にそのコミットメッセージが「どんな変更を行なったのか」がわかることが重要です。

## ローカルでマージするフローと、プルリクエストでマージするフローの違いは何でしょうか？
- ローカルでマージするフローは、自分のPCで main に反映し、そのまま pushするが、ブルリクエストでマージするフローは、GitHub 上で差分を確認して、レビューしてもらってからマージをすることです。

## コンフリクトを起こしてしまった場合、どう対処すべきですか？
- コンフリクトが発生しているファイルを開き、<<<<<<< HEADから=======、そして>>>>>>> 新しいブランチ名で区切られた箇所を確認します。

- コードを参考に、どちらの変更を採用するか、または両方を取り入れるかを判断し、手動でコードを修正して衝突マークを消します。

## コミットメッセージのプレフィックスとは？

単語や番号などの先頭に付加する要素で、何らかの意味や情報を表すものです。
単語や数字の前につけることで、その言葉や数値に新たな情報や意味を与えるものです。

## プレフィックスの例

- feat: 新しい機能の追加
- fix: バグ修正
- docs: ドキュメントの変更
- style: コードの動作に影響しない修正（フォーマットなど）
- refactor: リファクタリング（機能追加なし）
- test: テストの追加や変更
- chore: ビルドツールなどの更新
